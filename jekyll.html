What is Jekyll?
Jekyll is a static site generator. It takes templates, Markdown files, and configuration data, then builds them into a fast, secure website made of plain HTML, CSS, and JavaScript.
Section 2

Environment setup

Tasks

  • Install Ruby
  • Install Bundler and Jekyll
  • Verify the installation
  • Install a code editor such as Visual Studio Code

Mac example

Terminal commandsmacOS / Homebrew
# Install Ruby using Homebrew
# This gives you the Ruby language needed to run Jekyll
brew install ruby

# Install Jekyll and Bundler globally
# Bundler manages project dependencies
gem install jekyll bundler

# Verify that Jekyll installed correctly
jekyll -v

Windows note

Use RubyInstaller with Devkit on Windows. Then run:
gem install jekyll bundler
Section 3

Create a new Jekyll site

Terminal commandsCreate and run site locally
# Create a brand-new Jekyll site in a folder named my-business-site
jekyll new my-business-site

# Move into the project folder
cd my-business-site

# Start the local development server
# Jekyll will build the site and watch for file changes
bundle exec jekyll serve

# Open this in your browser:
# http://localhost:4000

Know the folder structure

  • _config.yml = site-wide settings
  • _layouts/ = page templates
  • _includes/ = reusable pieces like header/footer
  • _posts/ = blog posts
  • _site/ = generated site output, do not edit directly

Section 5

Sample site configuration

Place this in _config.yml.

_config.ymlSite-wide configuration
title: My Business Site
# The main title of your website

description: >
  Welcome to our business website built with Jekyll.
# A default site description used for SEO and metadata

url: "https://www.mybusiness.com"
# Your live website URL once deployed

baseurl: ""
# Leave blank if the site is at the root domain
# Example: use "/mysite" if hosted in a subfolder

markdown: kramdown
# Tells Jekyll which Markdown engine to use

plugins:
  - jekyll-seo-tag
  # Adds SEO tags such as title, description, Open Graph tags

  - jekyll-sitemap
  # Automatically generates a sitemap.xml for search engines

paginate: 5
# Number of blog posts per page when using pagination

paginate_path: "/blog/page:num/"
# URL pattern for paginated blog pages
Section 6

Main layout file

Create _layouts/default.html as your base template.

_layouts/default.htmlBase page layout with navigation and footer
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <title>{{ page.title }} | {{ site.title }}</title>
  <!-- Uses the current page title plus the site title -->

  {% seo %}
  <!-- Inserts SEO tags from the jekyll-seo-tag plugin -->

  <meta name="description" content="{{ page.description | default: site.description }}">
  <!-- Uses page description if available, otherwise falls back to site description -->

  <meta name="keywords" content="{{ page.keywords | default: '' }}">
  <!-- Optional keywords field from page front matter -->

  <link rel="stylesheet" href="/assets/main.css">
  <!-- Loads your site stylesheet -->

  <link rel="icon" href="/assets/favicon.ico">
  <!-- Browser tab icon -->

  <!-- Google Analytics: replace YOUR_TRACKING_ID with your real ID -->
  <script async src="https://www.googletagmanager.com/gtag/js?id=YOUR_TRACKING_ID"></script>
  <script>
    window.dataLayer = window.dataLayer || [];
    function gtag(){dataLayer.push(arguments);}
    gtag('js', new Date());
    gtag('config', 'YOUR_TRACKING_ID');
  </script>
</head>
<body>
  <header>
    <nav>
      <ul>
        <li>
          <a href="/{{ site.baseurl }}/" class="{% if page.url == '/' %}active{% endif %}">Home</a>
          <!-- Adds the class 'active' when the current page URL is / -->
        </li>
        <li>
          <a href="/{{ site.baseurl }}/about" class="{% if page.url == '/about/' %}active{% endif %}">About</a>
        </li>
        <li>
          <a href="/{{ site.baseurl }}/services" class="{% if page.url == '/services/' %}active{% endif %}">Services</a>
        </li>
        <li>
          <a href="/{{ site.baseurl }}/contact" class="{% if page.url == '/contact/' %}active{% endif %}">Contact</a>
        </li>
        <li>
          <a href="/{{ site.baseurl }}/blog" class="{% if page.url contains '/blog' %}active{% endif %}">Blog</a>
        </li>
      </ul>
    </nav>
  </header>

  <main>
    {{ content }}
    <!-- Jekyll inserts the content of each page here -->
  </main>

  {% include footer.html %}
  <!-- Loads a reusable footer file from _includes/footer.html -->
</body>
</html>

Section 9

Add a contact form

Because Jekyll creates static websites, forms need a third-party service such as Formspree or Netlify Forms.

contact.mdContact form using Formspree
---
layout: default
title: Contact Us
description: Contact our business for more information.
keywords: contact, form, email
---

# Get in Touch

<form action="https://formspree.io/f/your-id" method="POST">
  <!-- Replace your-id with your actual Formspree form ID -->

  <label for="name">Name:</label>
  <input type="text" id="name" name="name" required>
  <!-- required means the user must fill this out -->

  <label for="email">Email:</label>
  <input type="email" id="email" name="email" required>
  <!-- type=email helps browsers validate email format -->

  <label for="message">Message:</label>
  <textarea id="message" name="message" rows="5" required></textarea>

  <button type="submit">Send</button>
</form>

Deploy the website

Git setup and first push

Terminal commandsGitHub example
# Start a new Git repository
git init

# Add all files to Git tracking
git add .

# Save a first commit
git commit -m "Initial commit"

# Connect your local project to a remote GitHub repository
git remote add origin https://github.com/yourusername/my-business-site.git

# Push your code to GitHub
git push -u origin main

Deployment options

  • GitHub Pages
  • Netlify
  • Cloudflare Pages
After deployment, add your real domain name and enable HTTPS.
Section 12

Advanced features with annotated examples

1. Use data files for reusable structured content

Create _data/team.yml to store team member information in one place.

_data/team.ymlStructured data file
- name: Alice Johnson
  role: CEO
  bio: Experienced leader with 10+ years in business development.
  photo: /assets/team/alice.jpg
  # Each team member is an item in the list

- name: Bob Smith
  role: Lead Developer
  bio: Expert in web technologies and software architecture.
  photo: /assets/team/bob.jpg
about.mdUsing site.data in a loop
---
layout: default
title: About Us
---

# Meet Our Team

<ul>
  {% for member in site.data.team %}
    <!-- Loops through each item in _data/team.yml -->
    <li>
      <img src="{{ member.photo }}" alt="{{ member.name }}" width="100" />
      <h3>{{ member.name }} - {{ member.role }}</h3>
      <p>{{ member.bio }}</p>
    </li>
  {% endfor %}
</ul>

2. Add a blog section

Create posts in the _posts folder using the naming format YYYY-MM-DD-title.md.

_posts/2026-05-01-launch-announcement.mdSample blog post
---
layout: post
title: Launch Announcement
date: 2026-05-01
---

We are excited to announce the launch of our new business website built with Jekyll!
blog.mdBlog listing page
---
layout: default
title: Blog
---

# Latest Posts

<ul>
  {% for post in site.posts %}
    <!-- site.posts contains all blog posts sorted by date -->
    <li>
      <a href="{{ post.url }}">{{ post.title }}</a> - {{ post.date | date: "%B %d, %Y" }}
      <!-- The date filter formats the date nicely -->
    </li>
  {% endfor %}
</ul>

3. Add pagination to blog posts

blog.htmlPaginated blog page
---
layout: default
title: Blog
paginate: true
---

<h1>Blog</h1>

<ul>
  {% for post in paginator.posts %}
    <!-- paginator.posts contains only the posts for the current page -->
    <li>
      <a href="{{ post.url }}">{{ post.title }}</a> - {{ post.date | date: "%B %d, %Y" }}
    </li>
  {% endfor %}
</ul>

<div class="pagination">
  {% if paginator.previous_page %}
    <a href="{{ paginator.previous_page_path }}">Previous</a>
  {% endif %}

  Page {{ paginator.page }} of {{ paginator.total_pages }}

  {% if paginator.next_page %}
    <a href="{{ paginator.next_page_path }}">Next</a>
  {% endif %}
</div>

4. Add Google Analytics

Inside <head>Traffic tracking
<script async src="https://www.googletagmanager.com/gtag/js?id=YOUR_TRACKING_ID"></script>
<script>
  window.dataLayer = window.dataLayer || [];

  gtag('js', new Date());

  gtag('config', 'YOUR_TRACKING_ID');
  // Replace YOUR_TRACKING_ID with your Google Analytics ID
</script>

5. Highlight the active navigation link

Navigation exampleLiquid conditionals
<a href="/about" class="{% if page.url == '/about/' %}active{% endif %}">About</a>
<!-- If the current page URL matches /about/, Jekyll prints the class active -->
CSSActive state styling

  text-decoration: underline;

6. Create reusable includes

_includes/footer.htmlReusable footer component
<footer>
  <p>&copy; {{ site.time | date: '%Y' }} My Business. All rights reserved.</p>
  <!-- site.time gets the current build time, then the date filter extracts the year -->
</footer>
Use include in layoutDRY principle
{% include footer.html %}
<!-- This inserts the contents of _includes/footer.html -->

7. Add social sharing buttons to blog posts

_layouts/post.htmlShare links
<div class="social-share">
  <a href="https://twitter.com/intent/tweet?text={{ page.title | url_encode }}&url={{ site.url }}{{ page.url }}" target="_blank">
    Tweet
  </a>
  |
  <a href="https://www.facebook.com/sharer/sharer.php?u={{ site.url }}{{ page.url }}" target="_blank">
    Share on Facebook
  </a>
</div>

<!--
  page.title | url_encode
  = makes the title safe to use in a URL

  site.url + page.url
  = builds the full public link to the current post
-->
Section 13

Final checklist and notes

Launch checklist

  • Site runs locally with bundle exec jekyll serve
  • Navigation links work
  • Contact form submits successfully
  • Page titles and descriptions are set
  • Site is mobile-friendly
  • Images and assets load correctly
  • Site is deployed with HTTPS enabled

Maintenance checklist

  • Update content regularly
  • Back up the repository
  • Keep gems and plugins updated
  • Check analytics and site performance
